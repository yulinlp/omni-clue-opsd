## 1. 先直接回答：你描述的流程，旧版有；当前没有完整接回

你描述的过程可以理解成：**一个负责调查的模型，先读带时间戳的 caption，决定下一段要看哪里；程序把它要的音视频交给它，它再决定继续调查还是提交。**

旧版实现确实采用这个思路，而且下面三道题都有真实的 `inspect` 记录。当前 23 题重跑没有调用旧版这个循环，使用的是**程序规定步骤、模型在步骤内提出区间**的核验流程。

| 问题 | 旧版 agentic 标注 | 当前 v2 重标核验 |
| --- | --- | --- |
| 谁决定下一步？ | 模型选择 `inspect` 或 `submit` 等动作 | 程序根据当前阶段、疑点是否关键、盲答是否正确来分支 |
| caption 的作用 | 生成或复用时间戳 caption，供模型规划查看 | 把已有 caption 当作未核验草稿，结合全片重新整理事实 |
| 能否根据问题请求特定片段？ | 能；模型给起止时间、模态、fps、像素预算、查看目的 | 能；但在“关键疑点→局部复核”这个固定分支里执行 |
| 看完后能否自行连续要求别的片段？ | 能，在工具预算范围内持续循环 | 没有通用的连续工具循环；按固定步骤复核、回到全片整理，最多两轮重标 |
| 是否一直保留同一段对话？ | 同题 `messages` 持续追加，旧媒体按上下文预算裁剪 | 每阶段新请求；脚本显式传事实和失败反馈 |
| 停止条件 | 模型提交，或工具/轮次预算用完 | 双项核验通过；或两轮用完进入 `needs_review` |
| 提交是否等于标注正确？ | 不等于；协议和区间合法不保证语义真实 | 仍须 clue 盲答及 observation 核验通过才导出候选 |

所以，**当前仍有“让模型提出需要复看的区间”这个局部思想，但没有你描述的那种由主 agent 持续决定下一次查看的完整循环。**“使用同一个 Qwen API 客户端”也不等于“使用了原来的 agent 循环”。

另外，旧版也不是无限查看直到模型满意。本文三题的历史配置均为 `max_turns=12`、`max_inspect=6`、`max_media_in_context=2`；蛋挞和提示音题都实际触发过 `inspect budget exhausted`。这意味着它们的最终提交也受到查看预算限制。

## 2. 初学者可以怎样理解这几个对象？

- **caption**：像一份按时间写的视频笔记。它说“某时刻出现什么”，但可能认错人、听错话、记错时间；应拿它找线索，不能当标准事实。
- **inspect**：主 agent 提出的具体查看请求，例如“重看 14–20 秒，保留声音，确认是谁说了这句话”。程序负责切片和编码，模型负责理解返回的片段。
- **clue 区间**：最终交给回答模型的证据范围。主 agent 看过的所有片段，不一定都包含在最终 clue 中。
- **observation**：对这些证据的文字描述。它应该描述真正可见、可听的事实，以及受到证据支持的必要推断。
- **盲答**：另开一个请求，只给最终 clue 音视频、问题和选项，不给 gold、caption 或之前的分析。程序再把它输出的字母与数据集 gold 比较。
- **gold**：原数据集的参考答案。本次程序以它作评分标准；出现冲突时，不能仅凭 gold 或单次模型回复就断言哪边一定真实。

主 agent 可以提交“候选 clue + observation”；只有后续核验通过，才适合把它作为自动核验候选。即使通过，也不能把同模型多次赞同当成人工确认。

## 3. 当前流程实际怎样运行？

```text
全片音视频 + 问题选项 + 旧 caption + 上轮反馈
    ↓
事实整理：事实 / 推断 / 候选 clue / 不确定事项
    ↓
疑点分级（有疑点时）
    ├─ 非关键 → 继续
    └─ 关键 → 请求局部区间 → 切片复核 → 回到全片更新事实
    ↓ 关键疑点解决后
独立 clue 盲答
    ├─ 错误或 UNKNOWN → 有轮次则带反馈重标，否则 needs_review
    └─ 与 gold 一致
         ↓
clue + 候选事实 + gold → observation 写作
         ↓
写作疑点核验 + 全片逐声明审计
         ↓
通过则导出；未通过则重试或 needs_review
```

当前各阶段保存的模型名称均为 **`qwen3.8-omni-flash`，temperature=0**。盲答是输入隔离的独立请求，核验并没有换另一种模型。

本文三题每轮实际只产生 `facts → triage → blind` 三个阶段：疑点被判为非关键，没有走 `focus` 片段复核；随后盲答与 gold 不一致，停止这一轮。第二轮仍失败，最终为 `needs_review`。**这三题没有执行新的 observation 写作，也没有执行最终 observation 审计。**下文提到的旧 observation 来自历史标注，不能误认为本次重跑的新结果。

| 题目 ID | 问题 | 数据集 gold | 第 1 轮盲答 | 第 2 轮盲答 | 主要矛盾 |
| --- | --- | --- | --- | --- | --- |
| `tbxnShhc::task3` | 桌上有几个蛋挞？ | B：不确定 | C：两个 | C：两个 | 是否真的识别到了蛋挞，而不是其他糕点或器具 |
| `JYBseFUa::task1` | 谁说了“What does that mean?” | C：短发红裙女性 | A：短发彩色衣裙女性 | A：短发彩色衣裙女性 | caption、旧 observation、全片事实和盲答对说话人的归属互相冲突 |
| `khNHbdJY::task0` | 电子“didi”声响了几次？ | A：八次 | D：九次 | D：九次 | 没有建立可核对的逐事件时间表，候选片段和实际声音计数没有闭合 |

这些结论是**模型输出与参考答案的冲突分析**，不是对原视频答案的最终人工裁决。

## 5. 案例一：蛋挞计数——多看几段仍可能把对象认错

### 5.1 题目与历史标注

视频 `tbxnShhc.mp4`，约 216.56 秒，是虚拟咖啡店游戏画面。

```text
How many egg tarts are on the table?
A. Four.
B. I am not sure.    ← 数据集 gold
C. Two.
D. One.
```

旧 caption 已经包含咖啡制作、桌面、糕点展示等时间段。历史 agent 并不是只读 caption 就直接提交，它依次请求了：

| 次序 | 实际查看范围 | 模态/参数 | 想解决什么 |
| --- | --- | --- | --- |
| 1 | 85–105 秒 | video，2fps，156800 像素预算 | 找糕点和蛋挞展示 |
| 2 | 120–140 秒 | video，2fps，156800 | 看柜台、付款附近的物品 |
| 3 | 37–60 秒 | video，2fps，156800 | 查看制作拉花的桌面 |
| 4 | 0–20 秒 | video，2fps，156800 | 检查开头柜台 |
| 5 | 88–98 秒 | video，4fps，313600 | 更细看糕点，区分蛋挞与水果挞等 |
| 6 | 140–160 秒 | video，2fps，156800 | 检查其他相关物品 |
| 7 | 再次请求 inspect | 被程序拒绝 | 六次查看预算已经用完 |

它最后提交 `85–105`、`120–140` 秒，旧文字大意为“看到标为 Pancakes、Fruit Tart 的物品，没有确认蛋挞；另一个区间主要是茶盒、杯子”。这是**历史模型的描述**，其物体类别和标签仍需核实。

这就是你说的 agentic 思路的真实例子：它主动换区间，也把其中一段提高到 4fps。但最终结果并不能因为它“反复看了”就自动成为真值。

### 5.2 本次两轮发生了什么？

| 轮次 | 新 clue（原视频秒数） | 盲答输出 |
| --- | --- | --- |
| 1 | 93–96、124–128 | C，声称桌上清楚可见两个蛋挞 |
| 2 | 0–3、93–96、124–128 | C，声称拼接片段的 2–3 秒能看到两个盘子上的蛋挞 |

第 2 轮确实增加了开头 0–3 秒，不属于完全相同的请求。但“添加一个片段”并没有解决**它看到的物品到底是不是蛋挞**这个问题。

注意时间映射：第 2 轮盲答所说的拼接片段 2–3 秒，对应原视频 2–3 秒；第 1 轮拼接片段 0–3 秒才对应原视频 93–96 秒。不能把所有回复里的“2 秒”都当作同一原视频位置。

当前全片请求因文件预算降为 1fps、448×250；盲答短片为 4fps、640×360。文件包含声音，但该问题主要依赖视觉。保存的编码参数不保证云端内部逐帧都被使用。

### 5.3 为什么不能只把错误原因传回再答一次？

假设模型把咖啡器具或其他糕点认作蛋挞，那么“上次选 C 错了，请再看”并没有给它一个新的辨认依据。它可能换一段描述，仍坚持“两个”。这里至少有三种待分辨的情况：

1. 真有蛋挞，但旧标注/参考答案有问题。
2. 画面有类似糕点，模型把类别认错。
3. 画面不足以支持确定计数，题目设置了 B“不确定”作为有效选项。

已有静帧检查在约 95.5 秒发现糕点展示上的 `ApplePie` 标签线索，这会质疑“这些就是蛋挞”，但**几张静帧也不能证明整段视频没有蛋挞**。因此不能直接据此改 gold 或宣布核验通过。

### 5.4 如果接回 agent，下一步应怎样调查？【建议，尚未执行】

让主 agent 维护两个问题：“类别确认了吗？”、“若类别确认，数量确认了吗？”。先连续查看糕点展示及开头桌面，对可辨标签、形状、盘子、遮挡分别记录；必要时放大原始帧中的物体区域。放大只帮助看清已有像素，不会产生真实新细节。

若仍无法确认类别，就保留“不足以确定数量”，再独立判断是否支持题目 B。不要为了迎合 gold 把“没看清”写成“视频肯定没有蛋挞”。最终 observation 只描述确认过的对象和限制。

## 6. 案例二：说话人识别——看见谁，不等于这句话就是谁说的

### 6.1 题目与冲突

视频 `JYBseFUa.mp4`，约 55.10 秒，包含理发店对话和快速切镜头。

```text
Who just said, "What does that mean?"
A. A short-haired woman in a colorful dress.
B. A woman with an afro wearing a white jumpsuit.
C. A short-haired woman in a red dress.     ← 数据集 gold
D. A blonde woman wearing a pink blouse.
```

这个案例尤其值得看，因为**旧标注本身就与 gold 不一致**：

| 信息来源 | 实际描述/指向 |
| --- | --- |
| 数据集 gold | C，短发红裙女性 |
| 旧 caption 的 10–19 秒段 | 先描述站着的红衣女性；又描述坐着、红披肩下面穿彩色衣服的人，称坐着的人问了目标句 |
| 旧 agent 最终 observation | 明确写成 afro 发型、白衣、坐着的女性，并说“matches option B” |
| 本次全片事实/疑点整理 | 倾向红衣女性 C |
| 本次两轮独立 clue 盲答 | 都选彩色衣服女性 A |

这不是单纯“本次 observation 写得不好”。旧 caption、旧 observation 和新请求对人物的对应已经不稳定。如果直接把旧 observation 当 SFT 分析目标，模型就可能学到与参考答案不一致的解释。

### 6.2 旧 agent 实际做了什么？

它根据 caption 请求 **14–20 秒，AV，3fps，156800 像素预算**，目的就是识别目标句说话人的发型、衣服以及站/坐状态。随后提交 `15.5–18` 秒和上述 B 的描述，只调用了一次 inspect，没有用完六次预算。

这说明：模型会自主停止，但自主停止不代表它已解决矛盾。历史提交没有因“文字明确指向 B，而 gold 是 C”被独立语义关卡拦住。

### 6.3 当前两轮为什么没有带来进展？

两轮新 clue 都是 **10–18.5 秒**，盲答都选 A。两个盲答请求的 `request_sha256` 完全一致，输入媒体、提示和问题没有增加新信息；回复措辞有变化，但不能称为两份新增证据。

盲答理由称自己通过对话顺序、声音或嘴部动作认出彩色衣服的人。这里应区分“模型声称完成了嘴形匹配”和“我们已经独立确认嘴形匹配正确”。保存的理由属于待核对判断。

全片是 2fps、640×298，clue 是 4fps、640×298。4fps 的视频每隔约 0.25 秒保留一帧，而说话人归属可能依赖很短的嘴部动作、画外音和镜头切换；增加 fps 或连续上下文可以作为复核手段，但不能保证解决。

### 6.4 合理的 agent 下一步【建议，尚未执行】

应将冲突明确交给主 agent：“gold=C、旧 observation=B、当前盲答=A，请找出原始音视频里决定性的说话人证据。”不要只发“答错了”。

1. 连续看有前后文的约 12–20 秒，保留同步音频。
2. 先按人物建立身份表：站/坐位置、发型、衣服、是否有理发披肩，避免把披肩颜色当成裙子颜色。
3. 给每句台词一个时间段，分别记录“能听清的句子”和“确定的说话人”；切镜时若只能听到声音就标明画外音。
4. 对目标句检查可见嘴部动作、前后声音是否同一人，必要时查看更密集原始帧。
5. 仍不一致则交人工听看，而不是把 C 强行写进 observation。

这里应先解决“谁说了哪一句”，再决定最终 clue 多长。把更长的片段交给同一模型却不要求人物/台词对应，仍可能重复原错误。

## 7. 案例三：提示音计数——十段候选，不等于十声，更不等于 gold 八声

### 7.1 题目和旧 agent 的查看过程

视频 `khNHbdJY.mp4`，约 265.14 秒，是赛车画面，包含引擎、无线电和电子提示音。

```text
How many times does the electronic "didi" sound play in the video?
A. Eight.     ← 数据集 gold
B. Ten.
C. Seven.
D. Nine.
```

历史 agent 先后请求 **0–60、60–120、120–180、180–240、240–265.12 秒**的 audio 视图，覆盖了近乎完整音轨；第六次再听 0–30 秒。第七次 inspect 被预算限制拒绝。audio 请求里的 fps/像素参数不能解释成“模型看到同样的视频帧”。

最终它提交的 clue 却只有 **0–20、19–45、64–85、250–265 秒**，其中 19–20 秒还重叠。也就是说：**主 agent 听过全片，并不代表最终盲答器收到全片中的全部计数证据。**中段出现的声音可能根本没进最终 clue。

旧 caption 提到约 6 秒的双响，以及其他段落的提示音；旧 observation 有“通常会触发提示音”一类推测，没有列出八个已确认声音事件。这种写法不适合作为精确计数的直接依据。

### 7.2 新两轮实际结果

第 1 轮选择十个短段：

```text
0–3, 19–22, 64–67, 98–101, 115–118,
130–133, 150–153, 166–169, 171–174, 259–262 秒
```

盲答返回 D“九次”，理由是“除了第八段外，每段一次”。这已经给出了一个可定位的争议：第八段是原片 **166–169 秒**。但回复本身仍需听音核实。

第 2 轮仍是十个候选段，只做边界微调：

```text
1–3, 20–22, 64–66, 98–100, 115–117,
131–133, 150–152, 166–168, 172–174, 259–261 秒
```

仍答 D“九次”，这次理由只是笼统说听到了九次，没有逐个说明哪九次。程序没有据第 1 轮的计数差异建立事件表，也没有针对“第八段是不是同一种音效”发起额外听音请求。

另一个冲突是：旧 caption 说第一处约 6 秒，新 clue 却选 0–3/1–3 秒。caption 的时间可能错，也可能新定位遗漏了声音；目前不能把任一方当真值。

### 7.3 下一步该怎样做？【建议，尚未执行】

计数任务需要一张可核对的账，而不是一句“我数了九次”。建议每个事件保存：

| 字段 | 作用 |
| --- | --- |
| `event_id` | 同一个声音跨两个重叠片段出现，也只算一次 |
| 原视频开始/结束时间 | 防止拼接时间与原时间混淆 |
| 声音类别 | 区分目标电子双响、无线电、其他音效 |
| 计数单位 | 明确一次“di-di”按一个事件，而不是两个音符 |
| 支持片段与不确定点 | 能按按钮直接重听核对 |

主 agent 可优先要求连续重听 **0–9 秒**核对首声，及 **162–178 秒**核对有争议的第八候选和相邻候选，再按需覆盖其他部分。上述区间是本次分析提出的建议，未执行新的模型调用。

程序应按原时间去重，从确认的事件表算总数；agent 负责判断每个事件是否属于目标声音。若仍不能统一八次/九次，进入人工听音复核，不能为了达到 gold 人为删掉一个事件。

## 8. 为什么“多轮”不自动等于更可靠？

1. **相同输入可能只是重复判断。**当前 17 题中，12 题两轮 clue 区间相同，10 题两轮盲答请求哈希相同。
2. **更长的解释可能只是更完整地重复同一个误认。**蛋挞类别错了，再写几句计数理由也不会变对。
3. **caption 既帮助定位，也可能把错误带进后续请求。**说话人、食品标签、提示音时间都可能被继承。
4. **失败反馈需要变成具体取证动作。**说话人题应补台词与人物对应；计数题应补事件表；不能只统一再看全片一次。
5. **模型同意 gold 也不足够。**盲答关卡检查字母匹配，observation 关卡还要检查事实。反过来，模型不匹配 gold 也不自动证明模型错或 gold 错。

## 9. 怎样把你描述的 agentic 思路接回当前质量关卡？【实施建议，尚未接入】

```text
已有 caption / 原 clue 首轮核验
    ↓ 未通过，收集具体矛盾
调查 agent：维护人物表/事件表/事实表及未解决问题
    ↓ 自主提出 inspect(start, end, modality, fps, focus)
程序：校验区间与预算 → 切片 → 返回原时间映射与媒体
    ↓
调查 agent：更新证据；决定再看哪个区间，或提交候选
    ↺ 预算内循环；无新增证据时停止重复请求
    ↓ 提交候选 clue + observation + 证据表
隔离的 clue 盲答 → observation 逐声明核验 → 判决自洽检查
    ├─ 通过：自动核验候选，按计划再做人工抽检
    └─ 失败：剩余预算内带具体矛盾返回调查；否则人工队列
```

程序仍须掌握预算上限、输入隔离和是否导出的最终关卡。主 agent 可以决定“我看够了”，但不能自行宣布免检合格。建议把每次重看要解决的问题写进 `focus`，记录它是否解决；重复相同请求且没有新证据时停止自动空转。

盲答请求继续隔离 gold 与先前分析；调查和写作阶段若使用 gold，要明确记录。进入人工队列不等于已经完成人工审核；目前这些问题仍待处理。
