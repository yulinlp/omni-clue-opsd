# 多机训练通信入门笔记

## 1. 先记住这幅图

```text
worker-1：NPU 0～7，各有一份模型，各算不同样本的梯度
                         ╲
                          HCCL 汇总梯度 → 各卡使用同一份汇总结果更新模型
                         ╱
worker-2：NPU 0～7，各有一份模型，各算不同样本的梯度
```

本项目的双机训练采用数据并行：每张 NPU 保存一份模型，读取不同题目，独立完成前向和反向计算。若各卡只按自己的梯度更新，模型副本会逐渐不一致。因此，参数更新前必须通过通信汇总梯度。LoRA 微调时，主要同步的是**可训练 LoRA 参数的梯度**；冻结的基座模型不需要在每一步同步梯度。

一个极简例子：两张卡对同一参数算出的梯度分别为 `2` 和 `4`，汇总取平均后是 `3`，两张卡都用 `3` 更新这个参数。实际训练会同时对大量参数执行类似的集体通信，通常称为 **All-Reduce**。

### 哪些参数会计算梯度？

- **全参数训练**：通常对所有设为可训练、且参与本次计算的模型参数求梯度并更新。冻结的参数和非参数状态不会更新；某些条件分支中未用到的参数，也可能在该次计算中没有梯度。
- **LoRA 训练**：基座权重被冻结，主要对新增的 LoRA 参数求梯度并更新；若另行指定了可训练的偏置或模块，它们也会更新。基座模型仍参与前向计算，反向传播也须经过相关计算路径，因此显存和算力需求不会只剩下 LoRA 小矩阵。

上例的 `2` 和 `4` 是各卡从不同样本得到的**同一个可训练参数的梯度**，不是这个参数当前的数值。

## 2. 哪些信息会通信？

| 阶段 | 常见通信内容 | 目的 |
| --- | --- | --- |
| 启动 | 进程的 rank、总进程数、设备地址；必要时同步初始模型状态 | 让所有进程加入同一训练作业并从一致状态开始。 |
| 训练 | 可训练参数的梯度（主要流量） | 合并各卡所处理样本的信息，保持模型更新一致。 |
| 统计与保存 | 少量指标、同步信号 | 协调训练进度；通常由全局 rank 0 写主要日志和 checkpoint。 |

视频和问题一般由各进程从共享存储自行读取，**不会作为梯度同步的数据在机器之间逐条传送**。如果改用 ZeRO、FSDP 等参数切分方案，还可能频繁通信参数或优化器状态；上表描述的是本项目这类数据并行 LoRA 训练的主要情况。

## 3. “主节点”、`NODE_RANK` 和全局 rank

主节点提供 `MASTER_ADDR:MASTER_PORT`，让其他机器的进程找到它并完成**会合**。会合后，HCCL 在各设备间执行集体通信；主节点的 NPU 也照常计算。它不承担“收齐所有梯度、独自训练模型”的工作。

| 名词 | 含义 | 本项目 CLUE-OPSD 示例 |
| --- | --- | --- |
| `MASTER_ADDR:MASTER_PORT` | 会合地址，两台机器须填相同值。 | `172.16.12.237:29531`，位于 worker-1。 |
| `NODE_RANK` | **机器**编号，不是卡号。 | worker-1 为 `0`；worker-2 为 `1`。 |
| 全局 rank | 整个训练作业内每个进程的唯一编号。 | worker-1 的 8 卡为 `0–7`；worker-2 为 `8–15`。 |
| `RANK_TABLE_FILE` | Ascend HCCL 的设备/IP/rank 对照表。 | 双机 16 卡的子集表，rank 连续编号为 `0–15`。 |

SFT 在另一项 npu96 作业的 worker-10/11 上运行：worker-10 是 `NODE_RANK=0`，worker-11 是 `NODE_RANK=1`；当前开放问答 SFT 的会合地址为 `172.16.13.102:29523`。**主节点地址、机器 rank、全局 rank 是三种不同信息。**

## 4. 一次参数更新处理多少样本？

本项目两项双机训练均为 2 台机器、每机 8 卡、每卡小批量 1、梯度累积 2：

```text
全局 batch = 机器数 × 每机进程数 × 每卡 batch × 梯度累积次数
           = 2 × 8 × 1 × 2 = 32 条样本/次参数更新
```

“梯度累积 2”表示每个进程先把两个小批量的梯度累积起来，再进行一次参数更新。更新前各进程必须取得一致的汇总梯度；实际通信是在每个小批量还是累积完成时进行，由训练框架的实现决定。日志里的一个 `step` 指一次参数更新，并非只处理一条样本。

### 假设每卡 batch 改为 4，梯度累积仍为 2

| 每张卡上的顺序 | 做什么 | 此时是否更新参数？ |
| --- | --- | --- |
| 第 1 个小批量 | 同时处理 4 道题，把它们各自回答 token 的损失汇总为一个 batch loss，做 **1 次反向传播**。 | 否，只保留梯度。 |
| 第 2 个小批量 | 再处理 4 道题，汇总 loss，做 **第 2 次反向传播**，梯度累积到前一次的结果中。 | 否。 |
| 汇总与更新 | 各卡取得一致的汇总梯度，执行 **1 次参数更新**，然后清空梯度。 | 是；日志的 `step` 加 1。 |

此时每卡每次更新处理 `4 × 2 = 8` 条样本；16 张卡合计 `16 × 4 × 2 = 128` 次样本处理。**`batch_size=4` 对应一次处理 4 条样本、一次反向传播；`gradient_accumulation_steps=2` 对应两次反向传播后才更新一次。**

当每卡 batch 为 1 时，一个小批量通常是一道题目，模型依据这道题回答中的多个 token 计算 loss，再做一次反向传播。batch 为 4 时，框架一般把四道题的损失汇总后一次反向传播，不需要逐题反向传播四次。CLUE 可能复用或重复采样题目，因此“128 次样本处理”不保证是 128 道互不相同的题。

## 5. 遇到问题时如何判断

- **日志显示 `world_size: 16`**：16 个进程已组成同一训练作业；还需看到首个 loss/step，才能确认训练计算完成。
- **只有一台机器启动**：另一台尚未加入，会合会等待，超过超时时间可能报错。
- **rank table 或地址不一致**：即使各进程已启动，HCCL 建链或梯度同步也可能失败。
- **某一卡提前退出**：其他卡通常会在下一次集体通信处等待或报错，因为同步需要所有参与者。
