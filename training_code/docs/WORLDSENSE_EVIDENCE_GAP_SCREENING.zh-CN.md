## 1. 数据与预筛

**输入文件**：`output/worldsense_evidence_api_full/merged.evidence.jsonl`（3172 行，已完成全量标注）

预筛步骤（对应参考方案第 1 步）：

1. 仅保留 `status == "submitted"`：**3118 题**（排除 41 blocked 内容审核 / 11 no_evidence / 2 budget_exhausted）。
2. 时间戳合法性：所有区间满足 `0 ≤ start < end ≤ duration`（生成阶段已强制，做二次校验）。
3. 区间时长下限：`end − start ≥ 1.5s`（标注阶段的 `min_interval_seconds`）。

> 预期剩余 ≈ 3100 题（具体排除数在脚本报告中记录）。

## 2. 条件定义

| 条件 | 视频 | 音频 | 说明 |
| --- | --- | --- | --- |
| **Full** | 完整时间线 `[0, duration]` | 完整音轨 | 2 FPS 均匀采样（上限见 §3.2） |
| **Gold** | 证据区间拼接段 | 拼接段对应音轨 | 多区间 → 拼接（见下） |

**多区间拼接规则（默认）**：
- 用 ffmpeg concat 将各区间（含音轨）按时间顺序拼成单段 mp4：

```bash
# 1) 逐段无损切
ffmpeg -ss {start_i} -to {end_i} -i src.mp4 -c copy seg_i.mp4
# 2) 拼接（重编码以对齐时间基，音视频同步由 concat 保证）
printf "file 'seg_%d.mp4'\n" ... > list.txt
ffmpeg -f concat -safe 0 -i list.txt -c:v libx264 -preset veryfast -crf 20 \
       -c:a aac -b:a 128k -movflags +faststart gold.mp4
```

- 拼接产生的音频不连续点保留（与参考方案"证据片段"口径一致），在结果中记录拼接段数 `n_segments`。
- **稳健性对照**：在单区间子集（2140 题）上复核一遍，排除拼接引入的混淆。

## 3. 多媒体参数（核心）

### 3.1 模型事实（从 `config.json` / `preprocessor_config.json` 读取，非估计）

| 参数 | 值 | 来源 |
| --- | --- | --- |
| 上下文长度 | **32,768** token | `thinker_config.max_position_embeddings` |
| 视觉 patch | 14×14 | `preprocessor_config.patch_size=14` |
| 空间合并 | 2×2 → **28×28 px = 1 视觉 token** | `merge_size=2` |
| 时间合并 | **2 帧 → 1 个时间组** | `temporal_patch_size=2` |
| 音频 token 率 | **25 token/秒** | `thinker_config.position_id_per_seconds=25` |
| 音频采样 | 16 kHz，单声道，300s/块 | `n_samples=4,800,000`, `chunk_length=300` |
| 每帧像素上下限 | 3,136 – 12,845,056 | `min_pixels` / `max_pixels` |

**Token 公式（务必按"两帧合并"口径）**：

```text
视觉token = ceil(采样帧数 / 2) × (缩放后高度 / 28) × (缩放后宽度 / 28)
音频token = ceil(时长秒数 × 25)
总输入    = 视觉 + 音频 + 文本(预留 2,048)
```

### 3.2 主口径 A：动态预算（与训练输入同构，用于筛选）

规则（对齐参考文档 §6.2）：

1. 总上下文 32,768；文本预留 2,048（问题＋选项＋模板）。
2. `音频预算 = ceil(时长 × 25)`。
3. `视觉预算 = min(24,000, 32,768 − 2,048 − 音频预算)`。
4. 目标 **2 FPS**，**帧数上限 300**；不足时**减少均匀采样帧数但覆盖完整时间线**（即 `fps = min(2, 300 / 时长)`），音频**不因减帧而删减**。
5. `时间组数 = ceil(帧数 / 2)`；`每组预算 = 视觉预算 ÷ 时间组数`。
6. 处理器旋钮：**`max_pixels(每帧) = 每组预算 × 784`**，并 clamp 到 `[3136, 源分辨率]`（**不做上采样**）。
7. 显式保存 `nframes`、`resized_height/width`（28 对齐）与 `n_segments`。
8. 若 `视觉 + 音频 + 2,048 > 32,256`（预留 512 余量），按 10% 递减帧数重算。

| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 16s | 400 | 24,000 | 32 | 16 | 1,500 | 616×336（源上限） | 4,224 | 6,672 |
| 60s | 1,500 | 24,000 | 120 | 60 | 400 | 616×336（源上限） | 15,840 | 19,388 |
| 90s | 2,250 | 24,000 | 180 | 90 | 266 | 616×336（源上限） | 23,760 | 28,058 |
| 180s | 4,500 | 24,000 | 300 | 150 | 160 | 560×224 | 24,000 | 30,548 |
| 300s | 7,500 | 23,220 | 300 | 150 | 154 | 616×196 | 23,100 | 32,648 |
| 480s | 12,000 | 18,720 | 300 | 150 | 124 | 308×308 | 18,150 | 32,198 |

### 3.3 对照口径 B：固定低分辨率严格配对（用于归因）

与参考方案 §1 的历史筛选口径一致，**两条件使用完全相同的固定参数**，把差异归因到"媒体范围"本身：

| 参数 | Full | Gold |
| --- | --- | --- |
| 帧率 | 2 FPS | 2 FPS |
| 帧数上限 | 768 | 768 |
| 每帧 `max_pixels` | **28,672**（= 6×6 网格 = 36 tok/组 ≈ 18 tok/帧） | **同左** |
| 音频 | 全片 | 拼接段 |
| 模态 | av | av |

**该口径的 token 量（源 640×360）**：

| 时长 | 帧数 | 时间组 | 视觉 tok | 音频 tok | 合计+文本 |
| --- | --- | --- | --- | --- | --- |
| 16s | 32 | 16 | 576 | 400 | 3,024 |
| 90s | 180 | 90 | 3,240 | 2,250 | 7,538 |
| 300s | 600 | 300 | 10,800 | 7,500 | 20,348 |
| 657s | 768 | 384 | 13,824 | 16,425 | **32,297 ⚠️** |

> ⚠️ 657s 视频在该口径下会**略超上下文**（32,297 > 32,256）：处理方式 = 对 `时长 > 640s` 的视频把帧上限降到 720（或音频截到 640s），并在结果中标记 `budget_adjusted=true`。全量中受影响的视频约 **137 个（>384s 且接近上限）**，实际超限的更少。

**两口径的关系**：口径 A 用于**筛选**（贴近训练分布）；口径 B 用于**归因验证**（证明增益来自证据位置而非分辨率差异）。

## 4. 推理与答案评分

### 4.1 Prompt（筛查用，先出字母）

```
<video>
Question: {question}
Options:
A. {option_A}
B. {option_B}
C. {option_C}
[D. {option_D}]        # 仅 4 选项题
Answer with exactly one option letter (A/B/C/D). Do not explain.
```

- 系统提示（可选）保持两条件一致；**不允许推理链**（筛查要的是首 token 概率）。
- 与参考文档 §7.1 的训练/评测 prompt 保持字段一致（`Question:` / `Options:` / 选项行），便于后续训练复用。

### 4.2 评分

1. 取模型**第一个生成位置**的 logits，读取选项字母 token（`A`/`B`/`C`/`D`，均为单 token）的 logits。
2. 在**实际选项集合**上做 softmax 归一化（3 选项题只归一化 A/B/C）。
3. `prediction = argmax`；`P(GT)` = 正确选项的归一化概率；同时记录 `P_max`、`margin = P(GT) − P_max_other`、熵。
4. 一致性校验：`P(GT) ≥ 0.5` 且预测错误 → 单独记录（低置信噪声样本）。

### 4.3 确定性

| 项 | 设置 |
| --- | --- |
| 解码 | 贪心（`do_sample=False`），仅取首 token 概率 |
| 精度 | bfloat16 |
| 帧提取 | ffmpeg `fps=` 过滤器（确定性），帧序号写入结果 |
| 随机性来源 | 无（同一输入重复运行结果应一致；抽 20 题做重复性抽检） |
| 版本记录 | 模型路径、transformers 版本、ffmpeg 版本、脚本 git 版本写入产物头部 |

## 5. 指标

对每题计算（两条件成对）：

| 指标 | 定义 |
| --- | --- |
| `Δacc` | `1[Gold答对] − 1[Full答对]` ∈ {+1, 0, −1} |
| `Δp` | `P(GT\|Gold) − P(GT\|Full)` |
| `Δlogp` | 正确答案对数概率差（排序同分时使用） |
| 辅助 | `P(GT\|Full)`、`P(GT\|Gold)`、`pred_full`、`pred_gold`、token 用量、`n_segments`、`budget_adjusted` |

**汇总输出**：整体与**按任务类型**的 Full/Gold 准确率、准确率差（pp）、平均 Δp（对齐参考方案第 2 节表格）。

## 6. 筛选规则

**排序键**（降序）：`Δacc` → `Δp` → `Δlogp` → `P(GT|Gold)` → `question_id`（对齐参考方案第 2 步）。

**分层定义**：

| 分层 | 条件 | 用途 |
| --- | --- | --- |
| **Tier A（强增益）** | `Δacc = +1`（Full 错 → Gold 对） | 核心训练样本 |
| **Tier B（概率增益）** | `Δacc = 0` 且 `Δp ≥ 0.10` | 保留"双对/双错但证据显著抬升 P(GT)"的难题 |
| **Tier C（负增益，需审计）** | `Δacc = −1`（Gold 错 → Full 对） | **疑似标注错误**：进入审计队列，不进入增益集 |
| Tier D | 其余 | 备选/对照 |

**每视频上限**：5 题（同参考方案；WorldSense 平均 1.9 题/视频，实际很少触发）。

**规模建议**：先跑 pilot（§11）后按实际分布定目标规模（建议默认 `N = 2000`：Tier A 全部 + Tier B 按排序取满），并在报告中给出：
- 各 Tier 数量、Full/Gold 准确率、平均 Δp、覆盖视频数；
- **与参考方案的一致性**：集合级 gap 最大化（允许双对/双错入选）。

## 10. 风险与注意事项

1. **证据不是人类 gold**：WorldSense 没有官方 designated_segments，本项目证据来自 Qwen3.8-Omni-Flash 标注。因此：
   - `Δacc = −1`（Gold 反而答错）既可能是"模型不擅用证据"，也可能是**标注本身错误** → 必须人工审计 Tier C；
   - 报告需明确写"evidence = 模型标注"，与 OmniVideo 的官方证据不可直接对比。
2. **长视频的全片条件更苛刻**：WorldSense 中位 90s、最长 657s（OmniVideo 60–180s），Full 条件被预算压到更低每帧分辨率 → 预期 gap 更大，但需在结论中区分"证据位置增益"与"分辨率/时长难度效应"（口径 B 与区间外对照用于此）。
3. **3 选项题（188 道）**：评分必须按实际选项数归一化，prompt 也只列 3 个选项。
4. **音频不连续**：Gold 拼接段存在音频断点，可能影响音频类任务（402 题）的表现；用单区间子集与音频消融交叉验证。
5. **超预算边界**：`时长 > 640s` 的少量视频在两种口径下都需要微调（减帧或截音频），逐条标记 `budget_adjusted`，报告中单列。
6. **确定性**：同一输入应可复现；若发现不一致，先排查帧提取与 batching 的 padding 差异。
